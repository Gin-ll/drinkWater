## 需求 1：已喝实时刷新 + 精简卡片

**用户原文**：点击已喝时，不会实时刷新，只有下拉刷新后才会更新，优化成实时刷新，同时只保留已喝水按钮，删除未喝水，所有没有操作已喝水的都是未喝水状态，操作后一条信息只保留标题+状态以及滚动条左侧的时间。

**实现要点（我的理解）**：
- 首页时间轴需要**监听状态变更自动刷新**（当前点是「已喝」走的 `app.mark()` 只 `notifyListeners()`，但首页时间轴是 `FutureBuilder` 绑定了旧 Future，不会重建）- 修复方式：HomeScreen 给 AppNotifier 加 listener，变更即重载 `_future`
- 卡片**删除「未喝水」按钮**，只留「已喝水」一个动作按钮
- 状态语义二值化：**已喝水（有 drank 记录）/ 未喝水（其余全部）**；未来时刻建议保留「待提醒」以免误标（待确认）
- 卡片内容精简为：**左侧时间 + 标题 + 状态徽标**，去掉规则/正文副标题行

## 需求 2：只有当天才设闹钟

**用户原文**：只有今天的才会被标记成闹钟，过去的全都删除闹钟，只是一条简单的数据，未来的也不是闹钟，只有当天的才为闹钟。

**实现要点（我的理解）**：
- 调度策略改为 **当天一次性闹钟**：每天只为「今天」的触发点注册 1 个一次性闹钟
- 过去时刻：不设闹钟，仅保留数据；未来日期：不预排
- 带来的机制变化：循环提醒（每天/每周/每月）再次触发依赖**打开 App 时重新排当天闹钟**（以及开机广播恢复）；可考虑是否加「次日自动重排」
- 免打扰：当天触发点落在免打扰窗口内 → 完全跳过不排
- 附带收益：闹钟数量 = 启用提醒数，彻底远离安卓 500 上限（现在实现的是原生循环，也 OK，但用户明确要当天）

## 需求 3：手动喝水记录可编辑

**用户原文**：通过喝水按钮新增的记录同样可以进行编辑。

**实现要点（我的理解）**：
- 「喝水」按钮产生的是 `reminderId = null` 的手动记录
- 让点按该记录可打开编辑：
  - 可修改**记录时间**（同一天内调整 HH:mm，更新 `action_time`）
  - 可**删除**该条记录
  - 需要补充：数据库方法 `updateDrinkLogTime / deleteDrinkLog` + 状态层方法 + 首页弹窗
