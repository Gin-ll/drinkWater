# drinkWater 本地提醒 App · 设计文档

> 日期：2026-08-19 · 状态：已评审通过（待实现）
> 仓库：`https://github.com/Gin-ll/drinkWater.git` · 项目名：`drink_water` · Android 包名：`com.ginll.drink_water`

## 1. 目标

开发一款 Android 本地提醒 App（Flutter 实现）：

- 用户在 App 内自行输入提醒内容（标题 + 正文），设置提醒时间。
- 支持三种重复模式：一次性、每天、每周指定天。
- 到点后由系统级精确闹钟弹出标准系统通知（提示音 + 系统震动），无需 App 进程存活。
- 通知经手机上的「小米运动健康」App 通知监听转发到手环，实现手环震动提醒。
- 全部数据仅本地存储，无任何后端。

## 2. 非目标（YAGNI）

- 不做提醒触发历史/统计（统计页仅基于当前配置的静态统计）。
- 不做云端同步、账号体系。
- 不做闹钟式强提醒（全屏、持续响铃、稍后提醒）。
- 不做 iOS 支持（首个版本仅 Android）。
- 不引入图表库，统计图用基础控件绘制。
- 不做直接 BLE 透传手环、不逆向手环私有协议。

## 3. 技术选型

| 关注点 | 选型 | 理由 |
|---|---|---|
| UI | Flutter（Material 3） | 既定技术栈，本机 Flutter 3.44.8 可用 |
| 本地存储 | `sqflite`（SQLite） | 结构化、可靠、生态标准 |
| 定时调度 | `flutter_local_notifications`（基于系统 AlarmManager） | 系统级触发，进程被杀仍准时 |
| 时区处理 | `timezone` + `flutter_timezone` | zonedSchedule 需要本地时区 |
| 状态管理 | `provider` + `ChangeNotifier` | 规模小，够用且轻量 |
| 测试 | `flutter_test` + `sqflite_common_ffi`（内存库） | 数据层可离线单测 |

## 4. 架构总览

```
┌─────────────────────────────────────────────────────────┐
│                      UI 层（4 个标签页）                  │
│  首页(列表) · 添加(新建) · 统计 · 设置(小米引导)           │
└──────────────┬──────────────────────────────────────────┘
               │ provider / ChangeNotifier
┌──────────────▼──────────────────────────────────────────┐
│                    状态层                                │
│  ReminderListNotifier（列表、CRUD 联动、统计计算入口）    │
└──────────────┬──────────────────────────────────────────┘
        ┌──────▼────────┐        ┌───────────▼───────────┐
        │  Repository   │        │   NotificationService  │
        │  ReminderDAO  │        │   (调度核心封装)        │
        │  (sqflite)    │        │   推算+注册+刷新        │
        └──────┬────────┘        └───────────┬───────────┘
               │                             │
               ▼                             ▼
        SQLite 数据库               flutter_local_notifications
                                    → Android AlarmManager
                                    → 到点系统弹出通知
                                    → 小米运动健康转发 → 手环震动
```

数据流：任何增删改/开关切换 → Notifier 更新本地库 → 调用 `NotificationService.scheduleAll()` 全量刷新系统闹钟。

## 5. 数据模型

SQLite 表 `reminders`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK AUTOINC | 主键 |
| `title` | TEXT | 提醒标题（通知标题） |
| `body` | TEXT | 提醒正文（通知内容） |
| `repeatType` | INTEGER | `0`=一次性 · `1`=每天 · `2`=每周指定天 |
| `hour` | INTEGER | 触发时 `0-23`（一次性类型用 triggerAt） |
| `minute` | INTEGER | 触发分 `0-59`（一次性类型用 triggerAt） |
| `weekdays` | TEXT | JSON 数组如 `[1,3,5]`（1=周一…7=周日），仅每周型，其余 `null` |
| `triggerAt` | INTEGER | 一次性提醒的绝对时间戳（epoch 毫秒） |
| `enabled` | INTEGER | `1`=启用 `0`=停用（开关不删除数据） |
| `createdAt` | INTEGER | 毫秒时间戳 |
| `updatedAt` | INTEGER | 毫秒时间戳 |

设计要点：

- 循环型事件只存「时间分量」（hour/minute/星期几），不存日期 → 天然永恒重复；调度时按规则推算下一个触发点。
- 一次性事件存绝对时间戳，触发后由系统消耗闹钟，列表保留记录供用户手动删除；不做「已触发」标记。
- `enabled` 开关：关闭时撤销该提醒全部系统闹钟；重新打开时按规则重新注册。

## 6. 调度核心（NotificationService）

### 6.1 触发时点推算

| 类型 | 推算方式 | 注册方式（zonedSchedule） |
|---|---|---|
| 一次性 | 直接用 `triggerAt`，仅未来时间有效 | 单个一次性闹钟 |
| 每天 | 取今天/明天的该 `时:分` 中较近的未来时刻 | `matchDateTimeComponents: time`（每天循环，系统托管） |
| 每周指定天 | 对每个选中星期几分别注册 | `matchDateTimeComponents: dayOfWeekAndTime`（每周固定日重复） |

### 6.2 通知 ID 确定性方案

按 `reminder.id` 派生固定 ID 空间，便于「改规则后精准撤销旧闹钟」：

- 一次性 → `id * 100`
- 每天 → `id * 100 + 1`
- 每周 → `id * 100 + weekday`（1…7）

每次增删改/开关切换后执行 `scheduleAll()`：

1. 撤销所有提醒名下所有可能的 ID（遍历 ID 空间，规模小成本可忽略）。
2. 按新数据为所有启用提醒重新注册。

### 6.3 开机重调度

依赖 flutter_local_notifications 内置 `ScheduledNotificationBootReceiver`（Manifest 注册 `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` / `QUICKBOOT_POWERON`），重启/更新后自动恢复已注册闹钟。

> **实现期验证项**：目标小米机型重启后逐一验证循环与未过期单次提醒是否恢复。若发现遗漏，补写原生 `BOOT_COMPLETED` 广播接收器从 SQLite 重读并重注册作为兜底。

### 6.4 权限矩阵

| 权限 | 用途 | 时机 |
|---|---|---|
| `POST_NOTIFICATIONS` | Android 13+ 发通知 | 首次启动运行时申请 |
| `SCHEDULE_EXACT_ALARM` | 精确到分钟的触发 | 启动时调用 `canScheduleExactAlarms()` 检测，未授权跳系统「闹钟和提醒」设置页引导 |
| `RECEIVE_BOOT_COMPLETED` | 开机恢复闹钟 | Manifest 静态声明 |

### 6.5 通知渠道与交互

- 单个渠道「提醒」，`importance=high`，默认提示音 + 默认震动。
- 通知 payload 携带 `reminder.id`；点击通知 → 打开 App 并进入对应提醒的编辑页。

## 7. UI 设计（四标签页）

`NavigationBar` 底部导航 + `IndexedStack` 保留各页状态：

### 首页 —— 提醒列表

- 每条卡片：标题（粗体）、规则摘要（`每天 08:00` / `周一、三、五 09:30` / `8月20日 15:30`）、正文预览（单行省略）、右侧启用/停用开关。
- 点击卡片 → 编辑页；左滑或长按 → 删除（确认弹窗）。
- 列表按「下一次触发时间」升序排列（复用推算公式）。
- 空状态：「暂无提醒 · 点击下方 添加 新建」。

### 添加 —— 新建表单

- 标题（必填）、正文（多行选填）。
- 重复类型分段按钮：`仅一次 / 每天 / 每周`。
  - 仅一次 → 日期选择器 + 时间选择器
  - 每天 → 时间选择器
  - 每周 → 时间选择器 + 星期几多选 chips（至少选 1）
- 校验：标题非空；一次性时间须晚于当前；每周至少选一天；就地提示。
- 保存成功 → 切回首页刷新 + SnackBar 提示。

### 统计 —— 静态配置统计

- 提醒总数；类型占比（一次性/每天/每周）条形百分比（Container 宽度，不引图表库）；启用/停用计数；时段分布（早 05:00–11:59 / 午 12:00–17:59 / 晚 18:00–23:59 / 夜 00:00–04:59，区间不重叠）。
- 无数据时给空状态。

## 8. 小米适配

### 自动化可检测项（状态打勾 + 一键直达，直达失败降级为图文步骤）

| 项目 | 跳转方式 | 可靠性 |
|---|---|---|
| 通知权限 | `ACTION_APP_NOTIFICATION_SETTINGS` | 稳 |
| 精确闹钟授权 | `ACTION_REQUEST_SCHEDULE_EXACT_ALARM` | 稳 |
| 电池优化 → 无限制 | `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 稳 |
| 自启动 | 尝试打开应用信息页（MIUI 自启动入口各版本位置不同） | 尽力直达，失败降级图文 |

### 图文引导项（无法自动化）

- 小米运动健康已与手环绑定。
- 小米运动健康 →「消息通知」中开启本 App 开关。
- 手环未开启勿扰模式（否则不震动）。

### 排查顺序（设置页底部自诊清单）

- 手机不响 → 通知渠道声音/音量 → 精确闹钟授权 → 电池优化 → 自启动。
- 手机响但手环不震 → 小米运动健康「消息通知」开关 → 手环勿扰 → 本 App 通知权限。

## 9. 错误处理

- 数据库异常 → SnackBar 提示，不崩溃。
- 调度失败 / 权限中途被收回 → 设置页状态检测预警。
- 一次性时间已过（编辑场景）→ 表单校验拦截。
- 保存/删除操作的乐观更新 + 失败回滚提示。

## 10. 测试策略

### 单元测试（纯 Dart）

- 推算公式：一次性/每天/每周，含跨日、跨周边界用例。
- 校验逻辑：星期几选择、一次性时间必须为未来。
- ID 派生方案唯一性、撤销后无残留。
- 数据层 CRUD（`sqflite_common_ffi` 内存库）。

### Widget 测试

- 首页列表渲染、空状态、开关切换。
- 添加/编辑页校验提示。
- 统计页数值与占比计算。

### 真机手动验收矩阵（目标小米手机 + 手环）

- 前台/后台/进程被杀 三种状态到点准时触发。
- 每天、每周循环连续几天验证。
- 手机重启后闹钟自动恢复（6.3 节验证项）。
- 未授权精确闹钟时提醒被延迟的行为与引导。
- 手环实机全链路：触发通知 → 小米运动健康 → 手环震动。
- 关闭小米设置的若干项，验证引导页状态检测正确。
