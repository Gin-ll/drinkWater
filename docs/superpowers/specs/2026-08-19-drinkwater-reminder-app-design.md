# drinkWater 喝水提醒 App · 设计文档

> 版本：v2（2026-08-19，首版为通用提醒 App，本次按需求升级为「喝水管理 App」）
> 仓库：`https://github.com/Gin-ll/drinkWater.git` · 项目名：`drink_water` · 包名：`com.ginll.drink_water`
> 状态：待评审

## 1. 目标

开发一款 Android 喝水提醒与管理 App（Flutter 实现）：

- 用户自行设定喝水提醒：标题、时间点、循环方式（不循环 / 每天 / 每周指定天 / 每月固定日期）。
- 到点由系统级精确闹钟弹出标准通知，带 **「✅ 已喝水 / ❌ 未喝水」两个操作按钮**；通知同时经「小米运动健康」转发到手环震动提醒，手环上同样可点选两个按钮（实机验收项，见 §10）。
- 每次喝水的动作（已喝/未喝）写入本地记录，驱动首页时间轴与统计。
- 首页以**时间轴**形式展示今天的喝水时间点与是否已喝，支持快捷标记；点击条目进入编辑。
- 统计页支持按**周/月**查看：柱状图（每日喝水次数）、折线图（趋势）、日历（每日次数），点某天看当日喝水明细。
- 设置页（我的）：主题色切换（蓝色 / 黄色）、免打扰时段设置、小米适配引导。
- 全部数据仅本地存储，无任何后端。

## 2. 非目标（YAGNI）

- 不记录毫升数（仅统计喝水次数）。
- 不做云端同步、账号体系。
- 不做闹钟式强提醒（全屏、持续响铃）。
- 不支持 iOS（首版仅 Android）。
- 不做直接 BLE 透传手环、不逆向手环私有协议。
- 不提供「手动添加一杯」功能（喝水记录仅来自提醒触发后的点选）。
- 免打扰时段内到点的提醒**完全跳过、不补推、不记录**（已确认）。

## 3. 技术选型

| 关注点 | 选型 | 理由 |
|---|---|---|
| UI | Flutter（Material 3） | 既定技术栈，本机 Flutter 3.44.8 |
| 本地存储 | **`drift`**（类型安全 ORM，基于 sqlite3） | **关键**：通知操作按钮的回传需要在**后台 isolate** 写库，drift 原生支持后台 isolate（sqflite 仅支持主 isolate，做不到）；同时获得流式监听与类型安全 |
| 定时调度 | `flutter_local_notifications`（AlarmManager） | 系统级触发，进程被杀仍准时；支持通知操作按钮与后台动作回调 |
| 时区 | `timezone` + `flutter_timezone` | zonedSchedule 需要本地时区 |
| 图表 | `fl_chart` | 柱状图/折线图，轻量成熟 |
| 状态管理 | `provider` + `ChangeNotifier` | 规模中等，够用且轻量 |
| 系统设置跳转 | 自定义小型 MethodChannel（Native Intents 封装） | 通知设置/电池优化/精确闹钟/自启动等专项跳转 |
| 权限 | 各插件自带方法（`flutter_local_notifications`、`permission_handler`） | 通知、精确闹钟、忽略电池优化 |

## 4. 架构总览

```
┌──────────────────────────────────────────────────────────────┐
│  UI 层（底部 3 标签）                                         │
│  首页（时间轴） · 统计（图表/日历） · 设置（我的）              │
└──────────────┬───────────────────────────────────────────────┘
               │ provider / ChangeNotifier
┌──────────────▼───────────────────────────────────────────────┐
│  状态层  AppNotifier（提醒列表、当日流水、统计口径、监听流）     │
└──────┬──────────────────────────────────────┬────────────────┘
       │                                       │
┌──────▼──────────┐              ┌─────────────▼──────────────┐
│  数据层 drift     │              │ 调度层 NotificationService  │
│  reminders       │              │  · 90天窗口发生点推算(含DND) │
│  drink_logs      │              │  · 注册/撤销系统精确闹钟     │
│  settings        │              │  · 通知带操作按钮            │
└──────┬──────────┘              └─────────────┬──────────────┘
       │                            ┌──────────▼──────────┐   ┌───────────────┐
       │                            │ 后台回调处理:         │   │ 小米运动健康    │
       └──── SQLite ────────────────┤ · Boot 重注册        │   │ 通知监听 → 手环 │
                                    │ · 通知按钮→写喝水记录 │◄──┘ (按钮同链路)  │
                                    └─────────────────────┘   └───────────────┘
```

数据流：任何增删改/开关切换 → Notifier 更新库 → 调度层**全量重算 90 天窗口**并重注册。通知按钮被点（手机或手环）→ 后台 isolate 写 `drink_logs` → App 回到前台时刷新界面。

## 5. 数据模型（drift 三张表）

### `reminders` （提醒规则）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 主键 |
| `title` | TEXT | 标题（默认「喝水提醒」） |
| `body` | TEXT | 正文（默认「该喝水啦 💧」，可改） |
| `repeatType` | INTEGER | `0`=一次性 · `1`=每天 · `2`=每周指定天 · `3`=每月固定日期 |
| `hour` / `minute` | INTEGER | 触发时间分量 |
| `weekdays` | TEXT | JSON 数组 `[1..7]`（1=周一…7=周日），仅每周型 |
| `monthDay` | INTEGER | `1..31`，仅每月型；当月不足该日期时**取月末** |
| `triggerAt` | INTEGER | 一次性提醒的绝对时间戳（epoch 毫秒） |
| `enabled` | INTEGER | `1`=启用 `0`=停用 |
| `createdAt` / `updatedAt` | INTEGER | 毫秒时间戳 |

### `drink_logs` （喝水记录，统计的数据源）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 主键 |
| `reminderId` | INTEGER | 关联提醒（FK，可空） |
| `actionTime` | INTEGER | 用户点按的绝对时间戳 |
| `occurDate` | TEXT | 该次提醒归属日期 `YYYY-MM-DD`（按本地时区） |
| `isDrank` | INTEGER | `1`=已喝水 · `0`=未喝水 |

- 仅记录「发生过点选的提醒」；免打扰被跳过的场合不产生记录。
- 未喝水同样记录（用于当日明细的「漏喝」状态与今后可能的统计）。

### `settings` （键值表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | TEXT PK | 键 |
| `value` | TEXT | 值 |

键：`themeColor`（blue/yellow）、`dndEnabled`（0/1）、`dndStart`（`HH:mm`）、`dndEnd`（`HH:mm`，允许跨午夜）、`onboardDone`（0/1）。

## 6. 调度核心（NotificationService）

### 6.1 统一「90 天窗口调度」策略

**所有重复类型统一走同一条代码路径**，不再依赖系统原生循环闹钟，逻辑单一且天然适配 DND：

1. 对每条启用的提醒，推算**未来 90 天内**所有触发时刻：
   - 一次性：仅 `triggerAt`（未来有效）
   - 每天：每日该 `时:分`
   - 每周：仅选中星期几的该 `时:分`
   - 每月：每月第 `monthDay` 日的该 `时:分`，当月不足该数则取**当月最后一天**
2. 逐时刻剔除落在**免打扰窗口**内的触发。
3. 为每个保留的触发注册一个一次性精确闹钟。
4. 刷新时机：App 启动、回到前台（resume）、数据增删改、开关切换、(插件 BootReceiver 覆盖的) 手机重启后。

> 90 天窗口意味着需每 90 天内至少打开/重启一次 App；每次打开都会把窗口续满。100 条提醒 × 90 天的闹钟量对安卓系统完全可承受（AlarmManager 为轻量 PendingIntent）。

### 6.2 通知与操作按钮

- 单渠道「喝水提醒」，`importance=high`，默认提示音+震动。
- 每条通知带两个操作按钮：`已喝水`、`未喝水`（actionId 由 §6.3 的 ID 方案派生，按钮与触发 ID 同源）。
- 点按 → `flutter_local_notifications` 后台回调（App 被杀时同样可用）→ **drift 在后台 isolate 写 `drink_logs`** → 手机与手环走同一条链路。
- 点击通知主体 → 打开 App 首页。

### 6.3 通知 ID 方案

- 一次性触发 ID = `{reminder.id} * 10000 + {index}`
- 操作按钮 actionId = 同 ID 派生
- 全量刷新 = 撤销该提醒 ID 空间内所有 ID → 按新窗口重注册。

### 6.4 权限矩阵

| 权限 | 用途 | 时机 |
|---|---|---|
| `POST_NOTIFICATIONS` | Android 13+ | 首次启动申请 |
| `SCHEDULE_EXACT_ALARM` | 精确触发 | 启动检测 `canScheduleExactAlarms()`，未授权跳设置引导 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 后台不被杀 | 设置页引导 |
| `RECEIVE_BOOT_COMPLETED` | 重启后恢复闹钟 | Manifest 声明 + 插件 BootReceiver |
| `ACCESS_NOTIFICATION_POLICY`（可选） | 精确检测勿扰 | 视实现需要 |

## 7. UI 设计（底部 3 标签）

### 首页 —— 喝水时间轴

- AppBar：标题「喝水」+ 右上角 **+**（新建提醒，打开新页面）。
- 主体为今日时间轴：竖直时间线，每个已设时间点一个节点，显示：
  - 时间 + 标题
  - 状态徽标（按时间先后与记录综合判定）：
    - `待提醒 ⏰`：时间未到
    - `免打扰`：时间未到且落在免打扰窗口内
    - `已喝水 ✅`：存在 drank 记录
    - `未喝水 ❌`：存在 missed 记录
    - `未响应 -`：时间已过且无任何记录
  - 每个节点的快捷按钮：`已喝` / `未喝`（与通知按钮作用相同，立即落库并刷新）
- 点击节点 → 编辑页。
- 空状态：`今日暂无喝水提醒 · 点右上角 + 添加`。
- 「今日」固定在首页；历史日期在水统计→日历中查看。

### 新建 / 编辑提醒页

- 标题输入（必填，默认「喝水提醒」）、正文输入（选填）。
- 时间选择器（必选）。
- 循环方式：不重复 / 每天 / 每周 / 每月。
  - 每周：星期几多选 chips（一~日，至少 1），如周一、周三、周五。
  - 每月：日期选择 `1..31`。
- 校验：标题非空；一次性时间必须晚于当前；每周至少选一天。就地提示。
- 保存 → 返回首页并刷新。

### 统计 —— 周/月视图

- 顶部切换：本周 / 本月（及上月、前周等相邻切换）。
- **柱状图**：每日喝水次数（次/天）。
- **折线图**：每日喝水趋势（可切换 累计/每日）。
- **日历视图**：当月日历格子内显示当日喝水次数（色阶深浅表示多寡）；点击某日 → 当日喝水明细（该日每个提醒 + 状态 + 点数时间）。
- 无数据时空状态。
- 图表统一用 `fl_chart`，颜色跟随主题色。

### 设置（我的）

- **主题色**：蓝色 / 黄色 切换（立即生效，Material 3 ColorScheme）。
- **免打扰**：开关 + 起止时间（支持跨午夜），说明文案「期间提醒完全跳过」。
- **小米适配引导**：同 §8 清单。
- 关于：版本信息。

## 8. 小米适配（手环保真链路）

### 自动化可检测项（状态打勾 + 一键直达，直达失败降级为图文）

| 项目 | 跳转方式 | 可靠性 |
|---|---|---|
| 通知权限 | `ACTION_APP_NOTIFICATION_SETTINGS` | 稳 |
| 精确闹钟授权 | `ACTION_REQUEST_SCHEDULE_EXACT_ALARM` | 稳 |
| 电池优化 → 无限制 | `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 稳 |
| 自启动 | 尝试打开应用信息页（MIUI 各版本位置不同） | 尽力直达，失败降级图文 |

### 图文引导项（无法自动化）

- 小米运动健康已与手环绑定。
- 小米运动健康 →「消息通知」中开启本 App 开关（**手环能收到提醒的前提**）。
- 手环未开启勿扰模式。

### 手环操作按钮⚠️（实机验收最高优先级）

- 原理：安卓通知操作按钮 → 手环通知界面显示「已喝水/未喝水」→ 点按回传 → 写库。
- **必须实机验证**：目标手环型号是否支持第三方 App 通知按钮显示与回传。
- 降级方案：若不支持，手环仅展示提醒+震动，喝水记录改在手机 App 内点选，主链路不受影响（§10 单列验收条目）。

### 排查顺序（设置页底部自诊清单）

- 手机不响：通知渠道/音量 → 精确闹钟授权 → 电池优化 → 自启动。
- 手机响手环不震：小米运动健康「消息通知」开关 → 手环勿扰 → 通知权限。

## 9. 错误处理

- 数据库异常 → SnackBar 提示，不崩溃。
- 后台按钮写库失败 → 记录/静默失败并下次启动时补偿标记（同发生点由 App 侧定时对账，见测试）。
- 权限中途收回 → 设置页状态预警。
- 一次性时间已过（编辑）→ 校验拦截。
- 保存/删除乐观更新 + 失败回滚。
